VHW User Administration

How accounts and access work in the VHW system, and how a system administrator adds, changes and switches off users through the web, without the technical team.

The four access profiles

Every person gets exactly one profile. A profile is a set of Keycloak groups; the groups decide what the person can use and do. Give access only through these groups, never by adding single roles to a user.

Nobody can delete patients, tasks, organisations or locations through the portal: no profile has delete rights. Records that are no longer needed are made inactive instead.

Rules that always apply

  • One person, one account. Never share a login. Shared accounts make it impossible to see who changed what.
  • App or portal, never both. An account in both ANDROID_PRACTITIONER and WEB_PRACTITIONER is refused everywhere. Someone who needs both gets two accounts, for example lerato.mokoena for the app and lerato.portal for the portal.
  • Switch off, do not delete. When someone leaves, disable the account. Their history stays readable and the account can be switched on again.
  • Give passwords in person or by phone, never by e-mail or in a shared document.

Log in with your own system administrator account (realm opensrp). The admin console will soon only open from inside the Ministry network; outside it, ask the technical team. Practise on Test first.

Add a portal user (data manager or system administrator)

In the Keycloak admin console, realm opensrp:

  1. Users → Add user. Fill in Username (lower case, for example mpho.sello), First name, Last name and E-mail. Click Create.
  2. Tab Credentials → Set password. Type a temporary password and leave Temporary switched on: the person chooses their own at first login. Save.
  3. Tab Groups → Join group. Tick WEB_PRACTITIONER and Portal Data Manager (data manager) or WEB_PRACTITIONER and Super Admin (system administrator). Click Join.
  4. Check the Groups tab shows exactly those two groups and nothing with ANDROID in it.

Test: the person logs in at the web portal, sets a new password, and can open Organisations and Locations. A data manager sees no way to create users; that is correct.

Add a VHW or supervisor

A phone user needs more than an account: the app also needs a practitioner record and membership of a care team, which decides which households the phone downloads. Use the web portal for this; it creates the account and the practitioner record together. Only system administrators can do it.

1. Create the user (web portal)

  1. User Management → Add user. Fill in First name, Last name and Username. E-mail may stay empty.
  2. Set Mark as practitioner to Yes. For a supervisor also set Mark as supervisor to Yes.
  3. Application ID: bkm.
  4. User groups: ANDROID_PRACTITIONER and PROVIDER (VHW) or ANDROID_PRACTITIONER and SUPERVISOR (supervisor). Never WEB_PRACTITIONER. Save.
  5. Set the password (Credentials). For phone users the password must not be temporary: the app cannot ask for a new one.

2. Put the practitioner in a care team (web portal)

  1. Care Team Management → open the team for the VHW's area → Edit.
  2. Add the new practitioner as a participant. Save. Use one team per VHW: adding someone to every team makes the gateway refuse them.

Test: install the BKM app, log in with the new account, sync. The households of that care team appear.

Screen names can differ slightly between portal versions. If a field is missing, stop and ask the technical team rather than guessing; a phone user without a practitioner record or care team can log in but sees nothing.

Everyday changes

TaskWhereHow
Reset a passwordAdmin consoleUsers → the user → Credentials → Reset password. Portal users: Temporary on. Phone users: Temporary off.
Someone leavesAdmin consoleUsers → the user → switch Enabled off → Save. Do not delete.
Change a profileAdmin consoleUsers → the user → Groups: first Join the new group, then Leave the old one. Keep the rule app or portal, never both.
VHW moves to another areaWeb portalCare Team Management: remove the practitioner from the old team, add to the new one. The phone downloads the new area at the next sync.
Locked out after many triesAdmin consoleUsers → the user → turn off the temporary lock on the details page, or reset the password.

Many users at once

For a whole district, send the technical team a spreadsheet saved as CSV UTF-8 (comma delimited), without passwords. They create all accounts, practitioner records and care-team memberships in one step and check every row first.
